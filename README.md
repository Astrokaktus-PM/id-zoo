# Pet ID — веб-макет

Работающий веб-макет без трекеров. Открывается по адресу
**https://astrokaktus-pm.github.io/id-zoo/**

## Что это технически

Vanilla HTML + ES-модули, без сборки. Supabase — база, авторизация, хранилище.
GitHub Pages — выкладка. Ничего устанавливать не нужно: репозиторий и есть сайт.

## Перед первым запуском

Выполнить по порядку в Supabase → SQL Editor все скрипты из `sql/`:
001 → 002 → 003 → 004 → 005 → 006. Каждый идемпотентен, повторный запуск безопасен.

## Вход без почты

Пользователь вводит логин, приложение подставляет служебный адрес
`логин@users.petid.local`. Подтверждение почты в проекте выключено.
Цена решения названа прямо в интерфейсе: **восстановить забытый пароль нельзя**.

## Безопасность

Репозиторий публичный, значит publishable-ключ виден всем. Это допустимо
ровно потому, что доступ определяется политиками RLS, включёнными на каждой
таблице с момента её создания. Прямого `INSERT` в `pet_members` нет: участники
добавляются только через `invite_member()`, которая проверяет, что вызывающий —
владелец.

## Что уже работает (Ф1)

- регистрация и вход по логину;
- профиль владельца: имя, город, район;
- профили питомцев: вид, порода, пол, дата рождения, возраст;
- совместный уход: четыре роли, приглашение по логину;
- PWA: манифест и service worker, стратегия «сеть первична».

## Ф2: пять доменов

- ручные отметки по каналам опыта (у собаки и кошки — свои каналы);
- степени A–E по четырём ограничителям: еда, среда, здоровье, страх;
- пятый домен = опыт × потолок, расчёт в `js/d5.js` — точный порт `d5_model.py`;
- крупное число — среднее за 7 дней; у дня нет вердикта, есть «чего не хватило» и одно действие;
- полнота ниже 50% — оценки нет, вместо неё один вопрос;
- степени D и E — прямой текст «покажите врачу», а не число;
- режимы дня для собаки: пять из макета, пункт плана = отметки в каналах;
- экран «Как это посчитано»: строки расчёта, происхождение каждой отметки, что добрать.

Сверка с Python: `node test/d5_check.mjs` (фикстура собрана `test/d5_fixture.py`).

## П5: прогулки и карта

- «Начать прогулку»: с кем идём (несколько собак — одна прогулка на каждую, трек общий), с треком или без;
- «Прогулка идёт»: живая карта, карточка на каждого питомца, предупреждение о фоне;
- итог: человек сам решает, сколько минут пошло в «движение» и в «работу носом», для каждого питомца;
- отчёт: изменение балла дня по той же модели, без вердикта дня;
- «Рядом»: Leaflet + OpenStreetMap, фильтры слоёв, статусы и места — демонстрационные;
- приватная зона 150 м вокруг начала трека — обязательна, точки внутри не уходят на сервер;
- точки с точностью хуже 50 м не сохраняются; разрыв больше 60 с или уход вкладки в фон — «трек прерывался».

Проверка трека: `node test/track_check.mjs`.

## П6: здоровье, документы, календарь

- карта здоровья: прививки, обработки, уход, приёмы; срок — «действует до» или дата + повтор;
- «требует внимания» — просрочено или срок в ближайшие 30 дней;
- просроченная прививка или обработка ставит домену 3 системную степень B (85%) — спецификация модели, раздел 04;
- банк документов: снимок или файл → закрытый бакет `pet-docs`, путь `<pet_id>/<document_id>/<n>.jpg`, сжатие до 1600 px;
- распознавания нет: поля заполняет человек, запись из документа помечается «скан»;
- календарь по всем питомцам: сроки из карты здоровья, события, течка диапазоном;
- правила напоминаний: за 0/3/7/30 дней; напоминания видны только в приложении — рассылки нет.

Проверка сроков: `node test/health_check.mjs`.

## Чего ещё нет

Свой режим дня, погодное правило «дождь → Плохая погода», фоновая запись
прогулки, пауза, «снюхаться», распознавание документов, рассылка напоминаний, деньги.
Порядок и сроки — в документе «План сборки веб-макета».
